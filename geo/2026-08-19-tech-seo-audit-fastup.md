# Технический SEO-аудит fastup.by

## Итог одной строкой
Полный обход всей карты сайта не нашёл ни одной сломанной страницы, ни одного дубля мета и
ни одной проблемы со скоростью — вся техническая грязь сосредоточена в мете (30 из 53 title
длиннее обрезки, 13 description длиннее обрезки, два обрублены на полуслове) и в двух точечных
дефектах, которые бьют именно по цитируемости: листинг кейсов отдаётся без `max-snippet:-1`,
а пять подстраниц пиллара GAS доступны по двум адресам сразу.

## Что проверено
Полный обход карты сайта: 53 страницы 19.08.2026, инструмент `scripts/site_crawl.py`.
Данные: `geo/crawl-fastup-2026-08-19-full.json`.
Покрыты все 52 URL из `sitemap.xml` плюс листинг `/cases`, включая все 8 кейсов и все 5
подстраниц пиллара `/geo-audit-system/*`. Предыдущий частичный обход
(`crawl-fastup-2026-08-19.json`, 30 страниц) этот отчёт заменяет — в нём второй уровень
вложенности выпал целиком.

## Критично
Пунктов нет, и на полных данных это утверждение сильнее, чем было на тридцати страницах.
53/53 страницы отдают 200. Ни одного редиректа внутри карты, ни одной цепочки длиннее одного
шага. `canonical` совпадает с URL на всех 51 индексируемой странице. `X-Robots-Tag` не
выставлен нигде. Блок `duplicates` пуст и по `title`, и по `description` — на 53 страницах ни
одного повторяющегося заголовка. `h1_count = 1` на всех 53. `has_viewport: true` и `lang: ru-RU`
везде. Максимальное время ответа по всему сайту — 0.243 с. Ломающих индексацию находок нет.

## Отдельно: шаблон кейса (8 страниц + листинг)
Системной технической проблемы у шаблона кейса нет. У всех восьми: статус 200, `canonical`
совпадает с URL, ровно один H1, H1 и title разведены по формулировке (в отличие от статей),
JSON-LD `Article + CreativeWork + BreadcrumbList + Organization + Person`, время ответа
0.015–0.216 с в пределах общего разброса сайта.

Что видно только на полном срезе и что стоит внимания:

- **Ни на одном кейсе нет `FAQPage`.** У листинга `/cases` он есть, у всех восьми карточек —
  нет. Это подтверждает то, что записано в `CLAUDE.md` про `case-rewriter-geo`, теперь замером,
  а не по памяти.
- **`Review` есть ровно в одном кейсе** — `/cases/pridemotors-2-day-launch/`. В остальных семи
  отзыв не размечен (или его нет).
- **Кейсы расслоились по объёму вдвое.** Три подробных: `pridemotors` — 1785 слов,
  `kubdecor` — 1762, и всё. Пять коротких: 492–620 слов (`selauto`, `agrofamaly`,
  `oleg-climate`, `royalhouse`, `artblock`, `novogodnie-podarki`). Для цитирования это значит,
  что половина витрины — карточки на пол-страницы, из которых модели нечего извлекать, кроме
  одного факта.
- Мета в норме у семи из восьми, выбивается только `/cases/kubdecor-by/` (title 92, desc 166).

## Отдельно: подстраницы пиллара `/geo-audit-system/*` (5 страниц)
**Каннибализации между собой нет.** Все пять title уникальны и построены по одной схеме
«Название метрики (АББР) | FastUp GAS» (37–44 символа), все пять description уникальны и
описывают разные вопросы, все пять H1 уникальны, ни одного пересечения с родителем. Блок
`duplicates` по ним пуст. Как разведённый набор терминов это сделано правильно.

Три оговорки:

1. Два description обрублены на полуслове (п. 3 в «Важно»).
2. Все пять доступны по второму, плоскому URL через 301 (п. 5 в «Важно»).
3. Страницы шаблонно одинаковы по структуре: ровно 3 H2 и 605–664 слова на каждой. Само по себе
   это не дефект — это словарь терминов, где однородность уместна. Но H1 = title на всех пяти,
   то есть ни одна не занимает вторую формулировку интента («что такое небрендовая видимость»,
   «как измеряют знание о компании в ИИ»).

## Дубли
Дублей нет. Блок `duplicates` в данных обхода пуст и по `title`, и по `description`. На 53
страницах, включая 8 кейсов и 5 однотипных подстраниц пиллара, ни один заголовок и ни одно
описание не повторяются. Отдельно отмечу, что это редкий результат для сайта с CPT-архивами:
именно там обычно висит дефолтная мета плагина.

Единственное, что попало в блок `collapsed_duplicate_urls`, — 5 плоских URL подстраниц GAS,
которые 301-редиректят на вложенные. Это не дубли контента (индексируется одна версия), а
дефект внутренней перелинковки — разобран в п. 5 «Важно».

## Что не проверялось
- Нагрузочное тестирование, лог-анализ сервера.
- PageSpeed / Core Web Vitals — здесь измерялся только TTFB-прокси (время ответа).
- Заголовки безопасности и проверка на клоакинг.
- Фактическое присутствие страниц в индексе (GSC, Яндекс.Вебмастер) — обход показывает, что
  страница *разрешена* к индексации, а не что она *проиндексирована*.
- `llms.txt` целиком: краулер сохраняет первые 1000 символов, проверены вводная часть и блок
  услуг, хвост файла не читался.
- Перелинковка как карта, каннибализация FAQ между страницами, содержание текстов.
- GEO/ИИ-видимость — отдельный аудит (`geo-auditor`), здесь не оценивалась. Данные
  `crawl-fastup-2026-08-19-full.json` для него готовы, повторно краулить не нужно.
