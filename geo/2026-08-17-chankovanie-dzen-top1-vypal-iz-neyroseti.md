# Чанкование: «Топ-1 без прямого вхождения ключа → выпадение из Нейро/AI Overviews через неделю» (Дзен)

Прогон метода `geo/METHOD-chankovanie.md` для темы личного кейса из
`content/drafts/habr-sandbox-intent-seo.md` (кейс с цифрами: топ-1 Яндекса за 3 минуты,
Google — за 3 часа, выпадение из Нейро/AI Overviews через неделю, конкурент с 8 позиции,
три внедрённые правки: прямой ответ в первых 1–2 предложениях под H2, короткая выжимка
2–3 предложения там, где раздел — инструкция, отказ от искусственного семантического
ядра в пользу списка реальных подвопросов). Статью не пишу — это работа `content-writer`.

## 0. Декомпозиция интента (3 живых промпта → 12 подзапросов)

**Промпт 1** — «Почему сайт из топа не попадает в ответы нейросетей?»
- 1a боль/причина: почему сайт в топ-1 не попадает в AI Overviews / Яндекс.Нейро
- 1b сравнение: чем топ классического поиска отличается от места в ИИ-ответе
- 1c механика: как ИИ-поиск извлекает контент со страницы
- 1d метрики/контроль: как проверить, что сайт цитируется нейросетью

**Промпт 2** — «Как писать статью, чтобы её цитировала нейросеть?»
- 2a боль/причина: почему одни статьи цитируют нейросети, а другие нет
- 2b сравнение: структура для классического ранжирования vs структура для извлечения ИИ
- 2c механика: что такое чанк и как ИИ выбирает фрагмент для ответа
- 2d метрики/контроль: как проверить статью перед публикацией на цитируемость

**Промпт 3** — «Что делать, если сайт выпал из ответов ИИ, хотя топ-1 держится?»
- 3a боль/причина: почему позиция в органике сохраняется, а цитирование пропадает
- 3b сравнение: наш раздел vs раздел конкурента, который забрал цитирование
- 3c механика: query fan-out — почему один ключевой запрос не описывает интент целиком
- 3d метрики/контроль: какие правки возвращают материал в цитирование

Прогнаны 3 репрезентативных подзапроса (по одному-два узла из каждого промпта, метод не
требует прогонять все 12, если выбранные уже вскрывают держателей узлов и плотность поля):
«почему сайт из топа не попадает в ответы нейросетей», «как ии поиск извлекает контент со
страницы», «структура статьи для цитирования нейросетью».

## 4. Бриф для content-writer

**Формат:** Дзен, «Статья» (не «Пост»), ориентир объём — 3000–6000 знаков (короче версии
для habr, где кейс идёт на полный технический разбор; здесь — плотный кейс без раздувания).
Первое лицо («я»), без «мы». Без ссылок на fastup.by в теле, без имён и доменов конкурентов
(описательно: «сторонний сайт с восьмой позиции», «конкурент в выдаче»), без блока «Частые
вопросы», без цены/CTA. Заголовок короткий и служебный — не «Красивая фраза: пояснение», без
«Честно о…».

**Одна мысль поста (кейс, не коллаж):** реальный случай — статья вышла в топ-1 Яндекса за
3 минуты и в топ-1 Google за 3 часа без прямого вхождения ключа (за счёт смысловой полноты
интента), но через неделю пропала из Яндекс.Нейро и Google AI Overviews, уступив цитирование
конкуренту с 8 позиции органики. Причина — разница между тем, что нравится классическому
ранжированию (полнота смысла), и тем, что нужно для извлечения ИИ-поиском (прямой ответ в
первых словах под H2, компактный блок-выжимка). Три внедрённые правки вернули материал в
цитирование (без гарантии, что дело именно в них — корреляция, не доказанная причинность,
как и в исходном драфте).

**Опорная фактура (из `content/drafts/habr-sandbox-intent-seo.md`, ничего не добавлять):**
- Топ-1 Яндекса — 3 минуты после переобхода, топ-1 Google — 3 часа, без прямого вхождения
  ключа в заголовок/текст.
- Через неделю — сохранение позиции в органике, но потеря цитирования в Яндекс.Нейро и
  Google AI Overviews в пользу конкурента с 8 позиции.
- У конкурента: сжатый маркированный список из 4 пунктов в первых ~35 словах под H2. У нас
  было: авторское рассуждение на ~150 слов перед полезным фрагментом.
- Три правки: (1) прямой ответ в первых 1–2 предложениях под каждым заголовком, без разгона;
  (2) короткая выжимка 2–3 предложения там, где раздел — инструкция; (3) отказ от
  искусственного семантического ядра в пользу списка реальных подвопросов аудитории.
- После пересборки материал вернулся в цитирование — с честной оговоркой, что причинность
  не доказана железно (корреляция, могло измениться что-то на стороне поисковика).

**Термин, который можно использовать без выдумывания (используется в поле, не наш неологизм,
подтверждён отдельным файлом базы):** query fan-out / декомпозиция запроса —
`geo/2026-08-16-mehanika-dekompozitsii-zaprosov.md`. Уместно один раз назвать явление, не
разворачивать в отдельный теоретический блок — здесь личный кейс, не методичка.

**Чего не делать:**
- Не копировать формулировки из уже опубликованной vc.ru-версии (`vc.ru/id6078234/...`)
  дословно — Дзен требует уникальный текст, и это разные площадки с разным голосом.
- Не превращать пост в теоретический разбор конвейера RAG (retrieval/chunking/reranking) —
  этот узел плотно закрыт конкурентами (ashmanov.com и другие), наш козырь не теория, а
  единственный в поле воспроизводимый личный пример с датами и цифрами.
- Не добавлять сравнение GEO vs SEO — не наш угол для этого материала, узел уже занят
  медиа-блогами (seologic.by, sostav.ru, cweb.by), удлинит пост без пользы.
- Не разворачивать «как проверить цитирование» в чек-лист — не входит в формат личного
  кейса, максимум одна фраза о том, как сам заметил пропажу.
