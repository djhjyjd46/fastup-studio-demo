# Индекс видимости в ИИ-поиске — спецификация сервиса

Внутренний проектный документ. Пишется один раз, дальше правится решениями, а не
переписывается. Исполнение передаётся отдельной сессии — промпт в конце файла.

Решение, из которого это выросло: `../../decisions/2026-08-22-indeks-vidimosti-format-i-masshtab.md`.
Задача в тудулисте: `../../TODO.md`, раздел «Индекс видимости в ИИ-поиске — пилот».

## 1. Что это и чего это не делает

**Что это.** Публичный отраслевой замер: по фиксированному списку коммерческих запросов
отрасли собираются ответы трёх ИИ-систем и фиксируется, какие компании в этих ответах
упомянуты. Результат — наблюдаемый факт, воспроизводимый любым человеком с тем же
списком запросов.

**Чем это НЕ является, и это надо держать жёстко:**

- **Не рейтинг качества.** Мы не оцениваем компании, не сравниваем их услуги и не
  утверждаем, что кто-то лучше. Мы фиксируем, что говорит машина.
- **Не оценка сайта.** Внутренние метрики покрытия интентов используются для разбора,
  но их числа наружу не идут — см. п. 4.
- **Не витрина услуг.** На странице индекса нет наших кейсов, цен, кнопок заказа и
  упоминаний услуг. Причина — п. 6 и п. 8.

**Формулировка результата всегда фактическая:** «упомянута в 2 ответах из 15», не «низкая
видимость», не «слабый результат». Факт защищён, оценка — нет.

**Корреляцию не считаем и не заявляем.** Для неё нужны данные о заявках замеряемых
компаний, которых у нас нет и не будет. Слово «корреляция» на страницах индекса
недопустимо — за ним немедленно последует вопрос «с чем именно», и ответить будет нечем.
Мы фиксируем упоминания, и только их.

## 2. Данные: как устроен замер

| Параметр | Значение | Почему так |
|---|---|---|
| Компаний в выборке | 20–30 на отрасль | Число компаний не влияет на стоимость: меряются запросы, а не компании |
| Запросов | ~15 коммерческих, на языке клиента | Без брендов, без наших формулировок |
| Движки | Яндекс.Нейро, ChatGPT, Google AI Overviews | Покрывают реальный ИИ-трафик Беларуси. Больше движков не значит лучше: Perplexity и Copilot здесь почти не используются |
| Прогонов на запрос | 3, берётся медиана | Стандарт из `../../playbook/geo-method.md` |
| Периодичность | 1 раз в месяц, фиксированное число | Пропущенный цикл обесценивает весь ряд |
| Регион | Тот, который люди называют в запросе. Для B2B в Беларуси это Минск и область | Замер по всей стране вытаскивает наверх крупных, а внизу выборки не остаётся тех, кому можно продать |
| Единица замера | **Бренд, а не юрлицо** | Нейросеть пишет «Добра хата», а не «ООО "Добра хата"». В выборке хранятся оба: юрлицо для проверки живости по ЕГР, бренд для замера |

**Одна версия методики на весь замер, включая нас.** Мерить себя по одной версии, а рынок
по другой нельзя — сравнение станет невозможным.

**GAS 2.0 для индекса не нужен.** Индекс фиксирует один наблюдаемый факт (упомянута или
нет); версия стандарта в этом не участвует. GAS применяется там, где мы даём клиенту
оценку и рекомендации, то есть в аудите.

**Главный актив — не первый выпуск, а непрерывный ряд.** Текущий срез конкурент с бюджетом
покупает за неделю. Историю за 12 месяцев купить нельзя. Отсюда правило: лучше одна
отрасль двенадцать месяцев подряд, чем десять отраслей по одному разу.

## 3. Хранение данных

```
geo/index/
├── SPEC.md                             # этот файл
└── <отрасль>/
    ├── companies.md                    # выборка компаний + критерий включения
    ├── queries.md                      # список запросов (публикуется целиком)
    ├── 2026-09-data.json               # сырой результат прогона
    └── 2026-09-report.md               # разбор для внутреннего пользования
```

Сырые данные коммитятся в репозиторий — датированный коммит служит независимой фиксацией
приоритета по времени наравне с `datePublished` и Wayback Machine.

## 4. Что публикуется и что нет

**Публикуется:**

- Сколько компаний замерено, сколько из них появляется в ответах хотя бы раз.
- **Топ-5 с именами** и числом упоминаний.
- **Полный список запросов** — это и есть гарантия независимости: подменить результат
  нельзя, а вот подобрать удобные запросы можно, поэтому запросы открыты.
- Методика: движки, число прогонов, даты замера, дата следующего обновления.
- Разбор «что общего у топ-5» — качественно, не числом: «у всех пяти есть страница с
  ответом на вопрос X, у остальных её нет». Проверяется читателем за минуту.

**Не публикуется:**

- Полный список мест. Компании вне топ-5 в публичном списке не существуют.
- Числовые метрики покрытия интентов (косинус локальной модели) — шкала ни к чему не
  калибрована, объявлять пороги нельзя (`../2026-08-15-INTENT-COVERAGE-BENCHMARK.md`).
  **Граница проходит по способу получения числа, не по его формату.** «Есть ответ на 5
  вопросов из 7» публиковать можно — при условии, что все 7 вопросов опубликованы списком,
  а «есть ответ» проверяется глазами за минуту. Те же «5 из 7», полученные косинусом с
  порогом, публиковать нельзя: и число, и знаменатель зависят от наших настроек. Эмбеддинги
  остаются инструментом, который **находит** вывод; публикуется проверяемое утверждение.
  Следствие: модель эмбеддингов в публичной методике не упоминается — она не участвует в
  получении публикуемых чисел. Подбирать инструмент «чтобы звучало солиднее» запрещено.
- Любые интерпретации вида «эти компании хуже работают с клиентами».

**Почему только топ.** Названные в топе компании начинают сами ссылаться на индекс и
делиться им — а нам нужны входящие ссылки на первоисточник. Список аутсайдеров ссылок не
приносит, зато приносит вопросы «на основании чего». Semrush и Similarweb публикуют
победителей ровно по этой причине.

## 5. Структура страниц

**Раздел на основном домене, не поддомен.** `index.fastup.by` для поисковиков и моделей —
отдельный сайт с нуля, накопленный entity-граф fastup.by туда не переносится. Разделить
потом можно, склеить обратно — нет.

```
/indeks-vidimosti/                        # хаб: что это, список отраслей
/indeks-vidimosti/metodika/               # методика, одна на весь индекс, версионируется
/indeks-vidimosti/<отрасль>/              # текущий замер отрасли
/indeks-vidimosti/<отрасль>/<год-месяц>/  # архив выпусков
/indeks-vidimosti/company/<slug>/         # страница компании (правила индексации ниже)
```

**Методика — отдельная страница, не блок под каждой отраслью.** Она одинаковая для всех
отраслей: дублирование даёт каннибализацию и необходимость править в N местах. Вдобавок
это самостоятельный цитируемый объект — «как измерять видимость бренда в нейросетях»
спрашивают, и отвечать на это должны мы. Версионируется с датой, изменения — в changelog.
Содержание: как отбираются запросы, как запрос раскладывается на подвопросы, почему эти
движки, почему 3 прогона и медиана, что замер показывает и **чего не показывает**, как
повторить его самому.

**Структура «категория x период» взята у Рейтинга Байнета** (у них категория x год с 2010).
У нас период — **месяц**: в ИИ-выдаче год это вечность. Через 12 выпусков появляется
динамика — единственное, что конкурент с бюджетом не может купить, а только выждать.

**Страницы компаний — один тип записи, разная индексация.** Данные по каждой компании
сохраняются в любом случае, это дёшево. Но публичная индексируемая страница на каждую —
это постоянный URL с утверждением «компания невидима в нейросетях», гораздо уязвимее
отсутствия в списке, плюс сотни тонких страниц вредят домену. Поэтому:

- компании из топ-5 — страница открытая и индексируемая (им это выгодно, они будут ссылаться);
- все остальные — та же страница, но `noindex`, доступна по прямой ссылке, **которую даёт
  менеджер в звонке**. Персональный разбор нельзя загуглить — его нужно получить от человека,
  и это ровно тот повод для разговора, ради которого индекс затевается.

**Страница отрасли, порядок блоков:**

1. H1 с отраслью, регионом и месяцем замера.
2. Первый абзац — прямой ответ с числами (сколько замерено, сколько попадает в ответы).
   Это блок, который извлекает ИИ, поэтому цифры в первых ~40 словах.
3. Таблица топ-5.
4. Разбор: что общего у топ-5 — главная экспертная ценность страницы.
5. Методика: движки, запросы полным списком, число прогонов, даты.
6. FAQ.
7. Дата замера и дата следующего обновления.
8. Одна нейтральная ссылка вниз — на страницу с кейсами изменения позиции (п. 6).

**Разметка:** JSON-LD `Dataset` для самого замера плюс `Article` для разбора, обязательно
`datePublished` и `dateModified`. В день выпуска — сохранение страницы в Wayback Machine.

**Тексты страницы (H1, вводный абзац, FAQ, подписи) пишет субагент `content-writer`.**
В сессии-исполнителе их не сочинять — см. `../../CLAUDE.md`.

## 6. Кейсы: рядом, но не внутри

Кейс, измеренный по той же публичной методике, что и весь рынок, — доказательство другого
класса, чем обычный кейс на сайте. Но размещать кейсы на самой странице индекса нельзя:
страница перестаёт читаться как замер и становится витриной, и первый же недовольный
конкурент ударит именно сюда.

**Решение:** отдельная страница с кейсами «до и после» по той же методике, ссылка на неё —
внизу индекса, нейтральной формулировкой. Один клик, связка сохранена, независимость цела.

**Блок кейсов физически пустой ещё 3–4 месяца:** платных GEO-клиентов ноль, динамика
позиции видна с третьего замера. Проектируется сразу, наполняется позже.

## 7. Как это работает на продажи

**Индекс сам не продаёт ничего.** Он производит повод для звонка. Не будет обзвона — будет
красивая страница без заявок.

**Канал 1 — обзвон (основной, работает сразу).** Менеджер звонит компании из замеренной
выборки. Крючок — не название услуги, а факт про собеседника: замерили N компаний отрасли,
вот сколько раз появляется он, вот сколько раз появляются первые три, предложение —
15-минутный разбор, откуда нейросеть берёт лидеров. Это снимает главную проблему холодного
звонка по GEO: не надо объяснять незнакомую категорию в первые тридцать секунд.

**Канал 2 — страница как доказательство.** Человек после звонка идёт проверять, не развод
ли. Единственная задача страницы в продажах — закрыть недоверие: методика, даты, сырые
данные, воспроизводимость.

**Канал 3 — цитируемость (месяцы).** Оригинальные данные по белорусскому рынку —
единственный тип материала, который ИИ цитирует охотно, потому что аналога нет.

**Разграничение публичного и персонального:** место конкретной компании называется только
в звонке. Открытый полный список обесценил бы повод для разговора.

**Скрипт звонка и одностраничник разбора — обязательны ДО начала обзвона**, не после
(`../../TODO.md`, п. 6.0.2). UTM-метка на ссылке, которую даёт менеджер, — тоже до, иначе
цепочка «звонок → переход → заявка» не видна вообще.

## 8. Репутация: риски и защита

| Риск | Защита |
|---|---|
| «На основании чего вы нас так оценили» | Методика и сырые данные открыты, замер воспроизводим. Формулировка — факт, не оценка |
| Публичная негативная оценка чужих юрлиц | Публикуется только топ-5; остальных в публичном списке нет |
| Заброшенность | Одна отрасль, но ежемесячно. Протухший индекс бьёт сильнее, чем его отсутствие |
| «Вы меряете и сами же продаёте лечение» | Первая отрасль — чужая, не наша. Методика открыта, сырые данные публикуются |

**Своя отрасль (веб-студии, маркетинг) в первую волну не берётся.** Стартовать с замера,
где мы сами участник и окажемся высоко, — значит с первого дня получить репутацию
саморекламы, от которой потом не отмыться. Свою отрасль добавляем позже, когда у индекса
появится репутация, и публикуем своё место наравне со всеми.

**Проверка новизны (2026-08-22).** Формат в мире занят плотно: Semrush AI Visibility Index,
Similarweb GenAI Brand Visibility Index, 5W AI Visibility Index, EMARKETER. В русскоязычном
поле — AIMonitor.pro. **«Первые в мире» и «первые в СНГ» наружу не подавать** —
опровергается за минуту. Незанятая ниша реальна и формулируется иначе: белорусские
компании по белорусским коммерческим запросам этого никто не меряет.

## 9. Первый выпуск: загородное строительство, Минск и область

**Отрасль выбрана 2026-08-22 после проверки двух источников выборки.** Ранее рассматривались
имплантация (шаблон из англоязычных GEO-кейсов, повторяемый моделями по инерции),
бухгалтерский аутсорс и логистика — оба отпали, см. ниже.

**Почему загородное строительство:**

- **Прямо названо золотым ICP** в `../../expert/opinions/2026-08-21-geo-buyer-psychology-validation-high-ticket-icp.md`
  (стройка домов). Чек от 50 000 BYN, максимальная цена ошибки, вокруг много историй про
  брошенные объекты — покупатель идёт в ИИ именно за валидацией подрядчика.
- **Выборка уже готова:** 201 компания в базе Егора, из них **158 по Минской области**,
  с брендом, сайтом, телефоном и категорией.
- **Сезон работает на нас.** Конец августа — время, когда выбирают подрядчика на следующий
  сезон. Обзванивать можно сразу, ждать два месяца не нужно.

**Источник выборки — Excel-база Егора** (выгрузка Яндекс.Карт, март-май 2026), файл
`leads_with_site_clean.csv` в его каталоге `Documents/база`: 16 676 компаний с сайтами,
91 категория, вертикаль — строительство, ремонт, недвижимость.

**Живость компаний** проверяется кодом ответа сайта перед прогоном (база от марта-мая,
часть могла закрыться). Это минута работы скриптом.

**Почему не база ЕГР из CRM** (`tag='pointer'`, 9 103 активных ООО с ОКЭД). Она полноценная,
и пустое поле сайта означает лишь, что ЕГР сайтов не содержит, а не что сайта нет. Но там
хранятся **юридические названия** («ООО "Ле Контабль"»), а замеряем мы бренд. Чтобы её
использовать, нужен промежуточный шаг: найти сайт по названию, с сайта взять бренд, глазами
проверить сопоставление. Это неделя инфраструктуры вместо проверки гипотезы. **ЕГР-база —
источник для масштабирования на другие отрасли** (там все отрасли, а не только стройка) и
инструмент проверки живости; для пилота используется Excel.

**Запросы:** составляются под отрасль по методике (п. 5), ~15 штук, на языке покупателя,
без брендов. Черновик готовит исполнитель, финальную формулировку утверждает Егор.

**Отложенные отрасли:** бухгалтерский аутсорс — вторым выпуском в конце октября, после
отчётного пика квартала (в пик до них не дозвониться; сразу после — помнят перегруз и
открыты к разговору). Своя отрасль (веб-студии, digital) — не раньше, чем у индекса
появится репутация, см. п. 8.

## 10. Что считается успехом пилота

Не число просмотров страницы. **Проверяемая гипотеза одна:** поднимает ли фраза «мы
замерили N компаний вашей отрасли, вы не появляетесь ни в одном ответе» конверсию холодного
звонка в согласие на 15-минутный разбор — по сравнению с текущим скриптом.

Не поднимает — потеряна неделя, гипотеза закрывается записью в `decisions/`. Поднимает —
вторая и третья отрасль.

## Разбор конкурента (aimonitor.pro), сессия 2026-08-22 — что взять на страницу отрасли

Полная структура их категорийной страницы (`/index/banks`) снята и сверена с нашей.
Не копировать целиком — только то, что содержательно усиливает, без имиджевых блоков
(модалки, CTA на демо, футер с реквизитами — не подходит нашей модели).

**Взять — два реальных пробела, оба следующим шагом:**
1. **Разбивка рейтинга по интентам, не только общая таблица.** У них — «видимость банка
   по темам запроса» (кредиты/вклады/инвестиции отдельно). У нас данные для этого уже
   есть в `intent_map`, просто не выведены как «кто лидирует в конкретном интенте».
2. **Аналитический блок с написанными выводами**, не только цифры. Их пример: «топ-4
   держат 80% рынка», «лидер везде кроме одной категории», «видимость строят агрегаторы,
   не бренд». У нас такого текста нет — только сырые таблицы. Писать через
   `content-writer`, по свежим данным после каждого перезамера, не один раз.
