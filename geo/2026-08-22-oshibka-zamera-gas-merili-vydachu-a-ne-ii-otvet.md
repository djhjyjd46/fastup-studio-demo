# Ошибка метода: замеры GAS до 22.08.2026 мерили поисковую выдачу, а не ИИ-ответы

Найдено 2026-08-22 при разборе `scripts/geo_check.py` (GAS v1.4.2) под задачу отраслевого
индекса. **Затрагивает все замеры цитируемости, сделанные до этой даты**, включая базовый
замер 14.08 и опубликованный кейс.

## Что именно было не так

| Движок в отчётах | Что скрипт делал на самом деле |
|---|---|
| «Яндекс» | Yandex Cloud Search API v2 → собирал `doc → url + title` из **обычной органической выдачи**. Никакого ИИ-ответа |
| «Google» | XMLRiver `search_google/xml` → те же `doc → url + title` из **выдачи**. Блок AI Overview не запрашивался |
| «ChatGPT» | RouterAI, `gpt-4o-mini` **без инструмента веб-поиска** → модель отвечала из обучающих данных |

То есть ни один из трёх «ИИ-движков стандарта» не мерил генеративный ответ.

## Как это проявилось в цифрах

- **«0% в ChatGPT — слепая зона»** ($NVI_{comm}$ и $NVI_{edit}$ около нуля) — **артефакт**.
  Проверено 22.08 через OpenAI web search: с включённым поиском ChatGPT называет конкретные
  белорусские компании по локальным коммерческим запросам. Ноль означал не отсутствие
  видимости, а отсутствие поиска у модели.
- **«Цитируемость статей: Яндекс 45.0%, Google 26.7%»** и **«Видимость коммерции: Яндекс
  41.7%, Топ-1 по нише»** — числа, вероятно, честные, но они про **присутствие в
  органической выдаче**, а не про цитирование в ИИ-ответе. Ошибка не в счёте, а в подписи
  под ним.
- **План «Спринта 3»** (внешний PR ради прорыва в ChatGPT) строился на несуществующей
  проблеме.

## Что остаётся верным

- **Устранение галлюцинации** (нейросети путали FastUp с индийским брендом витаминов
  Fast&Up) — наблюдалось напрямую в живых ответах, не через этот скрипт.
- **Работа с сущностью** — Wikidata Q140964144, `sameAs`, JSON-LD. Факт, проверяем.
- **Рост позиций в поиске** — подтверждён GSC и Яндекс.Вебмастером независимо от GAS.
- **Клиент, сравнивавший FastUp с конкурентами через нейросети и выбравший нас** — прямое
  свидетельство, от замера не зависит.

История кейса верна. Неверны конкретные проценты и названия метрик под ними.

## Что делать (решение Егора 2026-08-22)

1. **Стандарт GAS не переписывать.** Метрики (NVI, CBK, PKS, PCL, SCG) сформулированы
   нормально — сломан был источник данных. Стандарт **дополняется одним обязательным
   пунктом: в методике фиксируется поверхность замера** (ИИ-обзор, а не выдача) и способ,
   которым она снята.
2. **Перезамер по правильным поверхностям.** Те же 44 интента, стоимость порядка десятка
   рублей. Правильные источники:
   - Google AI Overview — XMLRiver, `search/xml` + `ai=1`, блок `<ai><answer>` (base64) и
     источники `<item>`. **Работает, проверено 22.08.**
   - Яндекс — XMLRiver, `search_yandex/xml` + `ai=1`, платная опция **«Обзор от Алисы»**
     (25 руб/1000 + 10 руб наценки), включена Егором 22.08.
   - ChatGPT — OpenAI Responses API с инструментом `web_search` через ProxyAPI
     (~1 руб за поиск + токены). **Работает, проверено 22.08.**
3. **Старый baseline не выбрасывать, а переименовать.** Он валиден как замер органической
   выдачи и пригодится для сравнения «выдача против ИИ-ответа» — это отдельный полезный
   разрез, которого больше ни у кого нет.
4. **Кейс править по результатам перезамера, а не наугад.**

## Ограничение до перезамера

**Конкретные проценты из кейса клиентам не называть** — ни 45%, ни 41.7%, ни «Топ-1 по
нише GEO». Собеседник, который полезет проверять через Нейро, их не подтвердит.
Качественная часть (устранили путаницу с брендом, связали сущности, выросли позиции,
клиент сравнивал через ИИ и выбрал нас) остаётся полностью рабочей.

**Перезамер может улучшить кейс, а не ухудшить:** ChatGPT записан нулём по ошибке метода,
с реальным поиском там может оказаться не ноль.

## Побочный вывод, полезный за пределами исправления

Блок `<ai>` у XMLRiver отдаёт не только текст ответа, но и **список источников `<item>`**,
из которых он собран. Это готовый «граф источников» — отвечает на вопрос, откуда модель
берёт лидеров, без собственной разработки. Для разбора «что общего у топ-5» в индексе это
основной инструмент (`index/SPEC.md`, п. 4).
