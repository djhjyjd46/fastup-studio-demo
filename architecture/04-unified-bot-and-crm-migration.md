# Бот → Алеся + инструменты: вынос `telegram-bot.php`

Схема слоёв — [03](03-fastup-ai-studio-master-plan.md). Здесь — как разобрать монолит
`admin-microapps/microapps/cron/telegram-bot.php` (2 461 строка) и удалить его.

## 1. Что есть сейчас (сверено 17.09)

**Кто пишет в Telegram:**

| Отправитель | Что шлёт |
|---|---|
| Алеся `@FastupAgent_bot` (токен используется и из PHP) | новые лиды (549/616), эскалация 45 мин, перезвоны (дайджест и «пора»), задачи с кнопками, ИИ-ПМ, дайджест дедлайнов; личные напоминания операторам из Laravel (`callbacks:notify-due`) |
| `@FastUpCRM_bot` | **только** созвоны `calls-today`, `calls-soon` и запасной путь в старую группу `-1004210123221`, если отправка Алесей не прошла |
| `@FastUpHR_bot`, `@fastupby_wiki_bot` | не нужны |

**Кнопки:** приходят на вебхук Алеси (`/tg/webhook`), Node пересылает `lead:*`, `t:*`, `pm:*`
на PHP (`mode=tg-webhook`), `t:*` добивается само-вызовом `mode=tg-close-finish`.

**Расписание в планировщике hb.by:** `new-leads` (два правила: днём и ночью), `hot-escalate`,
`callbacks`, `callbacks-due`, `calls-today`, `calls-soon`, `calls-soon 15`, `task-soon 15`,
`pm-scan`, `pm-deadlines`.

**Мёртвое:** `tasks-rebuild` (в расписании нет — удалить, решение Егора), `patchnote`
(разовое), `fastupcrm_bot_lead_keyboard` (не вызывается), `tg-setup` (вебхук CRM-бота).
Живого кода в файле ~90%: проблема не в мёртвом коде, а в том, что точка входа, отправка,
вёрстка, кроны и кнопки свалены в один файл.

**Баг, который закрывается выносом:** `microapps-v2/includes/tg-task-sync.php:43` делает
`require_once` всего `telegram-bot.php` ради одной функции; код точки входа в веб-запросе без
`?key=` отвечает `403 forbidden` и делает `exit` — закрытие задачи в веб-CRM может обрываться.

**Две живые гонки:**
1. «Взял в работу» против `hot-escalate`: оба читают `_crm_hot_state = waiting`, оба пишут —
   лид одновременно у Светланы в 616 и «в работе» у Евгения.
2. Двойное нажатие `pm:ok`: оба читают `_crm_pm_proposal` до удаления → два проекта.

## 2. Цель

- В Telegram пишет только Алеся. `telegram-bot.php` удалён. У `@FastUpCRM_bot` снят вебхук.
- Всё, что умел бот, — **инструменты** на `tools.fastup.by`: их зовут серверные workflow,
  Алеся и Antigravity 2.0 у Егора и Евгения.
- Выборки и изменения состояния остаются **в CRM (PHP REST)** — одна загрузка WordPress на
  операцию, переход состояния атомарный. Node не собирает данные сотней REST-запросов.
- **Серверные workflow — код в Node без модели.** Модель — только в `pm-scan`
  (DeepSeek) и в коротком резюме `pm-deadlines`.
- **Часы — планировщик hb.by**, не таймер внутри процесса: рестарт pm2 не теряет окна.

## 3. Раскладка режимов

Имена новых эндпоинтов и инструментов — рабочие, уточняются при реализации.

| Режим | Инструмент (CRM REST → tools) | Серверный workflow | Модель |
|---|---|---|---|
| `new-leads` | `crm_leads_to_notify`, `crm_mark_lead_notified` | каждую минуту 9–20, раз в час ночью → карточки 549 (горячие) / 616 | нет |
| `hot-escalate` | `crm_hot_overdue`, `crm_escalate_lead` (только из `waiting`) | каждые 5 мин → удалить из 549, карточка в 616 | нет |
| `callbacks`, `callbacks-due` | `crm_list_callbacks` (`today` / `due`) | 09:00 и каждые 5 мин → 616 | нет |
| `calls-today`, `calls-soon` | `crm_list_calls` (есть) | 09:00, за 30 и 15 мин → **переезд с CRM-бота на Алесю** | нет |
| `task-soon` | `crm_list_tasks` (есть) + окно дедлайна | каждые 5 мин → карточка с кнопками, `message_id` в задачу | нет |
| `pm-deadlines` | `crm_tm_reports` (есть) | утро → дайджест 543 | DeepSeek, резюме |
| `pm-scan` | `crm_get_lead_activity`, `crm_pm_propose` (есть) | по расписанию → агент оценивает лида | DeepSeek |

## 4. Контракт инструментов

- **Атомарный переход.** Меняющий инструмент принимает ожидаемое состояние и возвращает
  `{changed: true}` или `{changed: false, current: …}`. Пример: `crm_take_lead(lead_id)` —
  `UPDATE … SET state='taken' WHERE id=? AND state='waiting'`; 0 строк → «уже передан
  Светлане». `crm_pm_accept` сначала удаляет `_crm_pm_proposal` с проверкой числа
  удалённых строк, потом создаёт проект.
- **Идемпотентность рассылок.** «Отправлено» — метка на сущности (`_crm_bot_notified`,
  `message_id`), не «крон отработал в 09:00». Повторный запуск не дублирует.
- **Одна загрузка WordPress на вызов.** Эндпоинт отдаёт готовый список со всеми полями для
  карточки, без N+1.
- **Аудит.** Все изменения — в журнал CRM с источником (`telegram`, `ai`, `antigravity`).

## 5. Серверная часть Node

- `src/workflows/*.ts` — по файлу на workflow; `POST /cron/:job` с секретом; планировщик
  hb.by вызывает через unix-сокет процесса (`SOCKET` в `http.ts`), мимо Cloudflare и WAF.
- Мьютекс на job (одного процесса хватает, образец — `exclusive()` в `kb.ts`);
  pm2 — fork, один экземпляр.
- Одна исходящая очередь на `chat_id`: все топики — один чат `-1003819058234`, лимит
  Telegram на группу ~20 сообщений в минуту; учитывать `retry_after`, проверять результат
  каждой отправки.
- `process.on('unhandledRejection')` → лог в топик 626, процесс не падает; каждый job в
  try/catch. Состояние бота пишется через `atomicWrite` (`kb.ts`), а не `writeFileSync`.
- Heartbeat: каждый job пишет `last_ok_at`; команда статуса показывает возраст по каждому —
  тишина отличается от «job умер».

## 6. Порядок переезда

1. **PHP, без смены поведения:** разнести `telegram-bot.php` по `microapps/includes/bot/`
   (tg-api, format, keyboards, jobs/*, webhook/*), имена функций не менять; удалить мёртвое;
   `tg-task-sync.php` подключает `includes/bot/bootstrap.php` вместо точки входа.
2. **PHP:** закрыть обе гонки атомарными переходами.
3. **CRM REST:** эндпоинты из §3; регистрация инструментов в `agent/crm-mcp/src/index.ts`.
4. **Node, по одному режиму:** workflow шлёт в служебный топик 626 параллельно с PHP → сверка
   день → перенос в рабочий топик → режим снимается из планировщика hb.by. Первыми —
   `calls-*` (последнее, что держит `@FastUpCRM_bot`), затем `new-leads` + `hot-escalate`,
   `callbacks*`, `task-soon`, `pm-*`.
5. **Кнопки:** вебхук Алеси вызывает инструменты напрямую, пересылка на `mode=tg-webhook`
   убирается.
6. **Вывод:** удалить `telegram-bot.php` и `includes/bot/*`, снять вебхуки `@FastUpCRM_bot`,
   `@FastUpHR_bot`, `@fastupby_wiki_bot`; отключить маршруты HR/тикетов в Laravel. Обновить
   `bots/*.md`, `microapps/cron/README.md` (там ещё пути vh155).

## 7. Проверка по каждому шагу

- Шаг 1: `php -l` по всем файлам; список функций до и после совпадает за вычетом удалённых;
  закрыть тестовую задачу в веб-CRM — запрос не обрывается, карточка в «Закрытые задачи» есть.
- Шаг 2: два одновременных `lead:take` + `hot-escalate` на тестовом лиде → одно состояние,
  одно сообщение; два параллельных `pm:ok` → один проект.
- Шаг 4: карточки в 626 совпадают с рабочими по составу за сутки; рестарт pm2 посреди
  `new-leads` → повторный запуск без дублей.
- Проверки прода — редкими одиночными запросами: частые GET с одного IP блокирует WAF hb.by.

  `crm_validate_lead` для ручной перепроверки из Antigravity.
