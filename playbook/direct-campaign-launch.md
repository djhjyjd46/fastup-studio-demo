# Запуск кампании в Яндекс.Директе через API: порядок работ

Регламент собран по итогам первого запуска (собственная кампания FastUp, 06–07.09.2026).
Переносится на клиентские проекты целиком: наша память сюда не попадает, только процесс.

Все скрипты лежат в `../scripts/`, токен — в переменной окружения `YANDEX_DIRECT_TOKEN`,
подключение и коды ошибок — в [[../integrations/yandex-direct]].

## 0. Доступ (один раз на аккаунт, до всего остального)

1. Создать кампанию в интерфейсе — **без неё страница настроек API недоступна** и заявку
   подать нельзя. Достаточно черновика.
2. Зарегистрировать приложение на `oauth.yandex.ru` → «Для доступа к API или отладки»,
   право `direct:api`. Redirect URI подставляется сам и не меняется.
3. Подать заявку на доступ в интерфейсе Директа, вкладка «Мои заявки». Рассмотрение —
   от часа до 7 дней.
4. **Песочница до одобрения не работает** (`error_code 58`), писать код «пока ждём»
   не на чем — планировать эту паузу как простой.
5. Токен получить обменом кода на `oauth.yandex.ru/token`, положить в переменную
   окружения. В репозиторий не коммитить ни токен, ни Client secret.

## 1. Семантика: от базисов к спросу

```
python scripts/direct_semantics.py --config <проект>-seeds.json --out <проект>-wordstat.json
```

Конфиг задаёт базисы (10–15 фраз), гео, обязательные корни (`must_have`), маркеры
коммерческого и информационного интента, явный мусор. Скрипт тянет Wordstat по каждому
базису, объединяет, классифицирует и **отдельно собирает кандидатов в минус-слова** из
информационных и мусорных фраз.

Чего ждать от данных: на 12 базисах выходит порядка 1500–2000 фраз, из них коммерческих
около половины, а среди «коммерческих» ещё останется мусор с высокой частотой.
Топ по частоте почти всегда обманчив — самая частотная фраза обычно не про услугу.

**Отбор в кампанию делается руками по смыслу**, машиной только подготовка. Ориентир:
30–60 фраз на тестовый бюджет, больше не нужно — трафика столько нет.

## 2. Проверка спроса и цены

Прогноз бюджета в интерфейсе (гео, месяц) по отобранным фразам. Из него берутся:

- **цена клика при объёме 62** — рабочий ориентир для ставок;
- **цена при объёме 100** — во сколько обходится верх выдачи (обычно вдвое-втрое дороже);
- потолок трафика: сколько кликов вообще существует в нише.

Потолок важнее цены. Если всего трафика меньше сотни кликов в месяц, кампания не окупит
даже времени на настройку — это стоит выяснить до сборки, а не после.

## 3. Объявления

В ЕПК все объявления **комбинаторные** (`RESPONSIVE_AD`): одно на группу, до 7 заголовков
(≤56 знаков) и до 3 текстов (≤81). Директ сам перебирает сочетания, поэтому пары А/Б
отдельными объявлениями не нужны: варианты с **разными смысловыми акцентами** кладутся в
одно объявление. Цена в заголовке отсекает нецелевых до клика: это дешевле любых
минус-слов. Обещания результата не писать — только то, что реально выполняется.

Второго заголовка в комбинаторном объявлении нет. Правка — только через `ResponsiveAd`
в `/json/v501/` (`scripts/direct_apply.py`, блок `ads`). Официально: `api-docs/update-tga.md`
в папке `ads/`.

## 4. Сборка

```
python scripts/direct_create_campaign.py <проект>.json
```

Кампания создаётся **остановленной**. Ключевые решения по умолчанию: Единая перфоманс-
кампания (ручные ставки доступны только в ней), только поиск (`SERVING_OFF` в сети),
ограничение расхода — **недельный лимит** (дневной бюджет в ЕПК не применяется и
конфликтует с недельным).

## 5. Приёмка — обязательный шаг

```
python scripts/direct_lint.py <campaign_id>
```

Пока линтер не отвечает «замечаний нет», кампания не запускается. Он проверяет то, чего
нет в документации API:

- ставка больше четверти дневного лимита (один клик съедает день);
- широкая фраза одной группы перехватывает уточнённую фразу другой (кросс-минусовка);
- минус-слово блокирует собственную фразу;
- дубли фраз между группами;
- отсутствие UTM, быстрых ссылок, уточнений, счётчика, гео;
- автотаргетинг торгуется дороже собственных фраз.

Приёмку повторять **после каждого расширения семантики**: на 16 фразах пересечений может
не быть, на 39 их уже пять.

## 6. Аналитика до запуска, не после

Счётчик Метрики привязать к кампании, UTM с подстановками `{ad_id}` и `{keyword}` —
в ссылки. Проверить, что цель на заявку реально срабатывает: посмотреть достижения за
прошлый период, а не наличие цели в списке. Автоцель «отправка формы» обычно ловит и
AJAX-формы — тогда правка кода с `reachGoal` не нужна.

## 7. Запуск

Отправить объявления на модерацию (`Ads.moderate`), снять кампанию с паузы
(`Campaigns.resume`). Объявления в статусе `MODERATION` показывают `State: OFF` — это
не остановка, включать их вручную не нужно.

## 8. Ведение

- **Через 2–3 дня после старта** — первая чистка:
  `python scripts/direct_report.py <id> --queries --days 3`, мусорные запросы в минус-слова
  через `direct_apply.py`. Широкие фразы без этой чистки съедают половину бюджета.
- Раз в неделю — сводка: расход, реальный CPC против прогнозного, заявки по цели,
  записи визитов из рекламы.
- Оценивать по **марже с закрытых сделок**, а не по числу заявок, и не подставлять в
  расчёт цену «от N» из прайса.

## Грабли, стоившие времени на первом запуске

| Что | Как проявилось |
|---|---|
| Адрес API для ЕПК | В документации `/v501/`, работает `/json/v501/`; первый отвечает ошибкой 8000 на JSON |
| Ручные ставки | Недоступны в обычной текстовой кампании, только в ЕПК |
| Второй заголовок | `Title2` склеивается с первым через «. », если вместе меньше 56 знаков, **иначе теряется**. 16.09 API ответил «обновлено 8 из 8» с недокументированным предупреждением 10252 и ничего не записал |
| `TextAd` на комбинаторном объявлении | Правка через `TextAd` оставляет в объявлении **один** заголовок и один текст — стирает все добавленные варианты |
| Комбинаторные объявления в v5 | `ads.update` с `ResponsiveAd` в `/json/v5/` — ошибка 3500 «используйте v501». Операции в одном вызове не атомарны: 16.09 остановка объявлений прошла, правка заголовков нет |
| Ответ «успешно» | Не доказательство записи. После любой правки объявлений перечитать их через `ads.get` с `ResponsiveAdFieldNames` |
| Автотаргетинг в API | Поле `AutotargetingCategories` устарело: «узких запросов» в нём нет, `COMPETITOR` противоречит настройке брендов. Читать `AutotargetingSettings` — в `keywords.get` через **отдельные** параметры `AutotargetingSettingsCategoriesFieldNames` и `AutotargetingSettingsBrandOptionsFieldNames`, не через `FieldNames`. Менять — `keywords.update`, тот же `AutotargetingSettings` |
| Дневной бюджет | В ЕПК не применяется, конфликтует с недельным лимитом (ошибка 4004) |
| Ставки из прогноза | Это верхняя граница аукциона, а не рекомендация: доходили до 32 BYN при дневном лимите 21 |
| Минус-слова | Директ схлопывает словоформы по лемме: из 119 остаётся 96, покрытие не теряется |
| Сервис визиток | В API ЕПК отсутствует, контакты идут из Яндекс.Бизнеса |
| Баланс | Только в API v4 Live (`AccountManagement`), в v5 сервиса нет |
