# Figma to CMS / Production Web Pipeline

This skill guides the end-to-end process of transforming a Figma design into a robust, high-performance production website with an intuitive client admin panel, pixel-accurate responsive layout, zero cumulative layout shift (CLS), and mandatory high-conversion UX polish.

---

## Universal Semi-Prompt for Neural Figma Generation (The Design-to-Code Contract)

When generating a website layout in AI design tools (Figma AI, Galileo, v0, etc.), **ALWAYS append this universal, topic-agnostic design contract** to your prompt. It guarantees that the generated design strictly respects web development standards, eliminating 95% of subsequent layout bugs:

```text
[UNIVERSAL WEB DESIGN & TAILWIND COMPATIBILITY CONTRACT]
1. CANVAS & CONTAINER:
   - Desktop artboard: 1440px width.
   - Main content container: Exactly 1400px width, centered.
   - Outer horizontal padding: 20px on each side (1400px inner + 2*20px = 1440px).
   - Mobile artboard: 390px width with 16px outer padding.

2. STRICT 8PT / 4PT SPACING GRID (NO ODD PIXELS):
   - ALL margins, paddings, gaps, and component heights MUST strictly follow the Tailwind 4px/8px scale:
     [4px, 8px, 12px, 16px, 20px, 24px, 32px, 40px, 48px, 64px, 80px, 96px, 120px, 160px].
   - STRICTLY FORBIDDEN: Arbitrary or odd pixel dimensions (e.g. 9px, 15px, 23px, 37px). Every spacing value must map cleanly to Tailwind utilities (gap-2, gap-4, gap-6, gap-8, gap-12, etc.).

3. STANDARD TAILWIND BREAKPOINTS:
   - Design layout behavior strictly conforming to standard web breakpoints:
     sm (640px), md (768px), lg (1024px), xl (1280px), 2xl (1440px).

4. AUTO-LAYOUT FIRST (NO ABSOLUTE POSITIONING):
   - Every section, row, card, and button MUST use Auto-Layout (Flexbox).
   - Columns: Set layoutMode to HORIZONTAL with explicit itemSpacing (e.g. 24px, 32px, 48px). Use HUG for content-based columns and FILL for stretching columns.
   - NEVER create fake 12-column grids when standard Flexbox gap rhythm is intended.

5. EQUAL-HEIGHT CARDS & SPACE-BETWEEN DISTRIBUTION:
   - When cards in a row or column share the same height (e.g. 298px or 608px), divide the card content into exactly TWO distinct Auto-Layout child groups:
     a) Top group: Icon, badge, or tag.
     b) Bottom group: Heading, body copy, and action button.
   - Set primaryAxisAlignItems to SPACE_BETWEEN so top and bottom elements anchor cleanly to opposite edges.

6. FLAT / MINIMAL FORMS (NO UNREQUESTED CARD WRAPPERS):
   - Do NOT wrap form inputs in heavy decorative cards, rounded surface boxes, or exaggerated drop-shadow containers unless explicitly requested.
   - Inputs, labels, and submit buttons should rest cleanly on the section surface, using subtle borders and typography hierarchy.

7. INTERACTIVE STATES & CONVERSION "SUGAR" WIDGETS:
   - Always design explicit hover, active, and focus states for all interactive elements (buttons, cards, links, tabs).
   - Design essential conversion widgets directly into the design system:
     a) Non-intrusive Cookie Consent banner (floating bottom corner, minimal styling matching theme).
     b) Floating Scroll-to-Top button (bottom-right).
     c) Sticky quick-contact CTA / Messenger widget (Telegram, WhatsApp, Call).
     d) Micro-interactions: subtle border-glow, scale, or color shifts on card hovers (200ms-300ms transitions).
```

## The Neural-to-Neural Divergence: Why AI Code Diverges from AI Figma (And How to Prevent It)

When both the design (in Figma) and the code (in Web) are generated by AI/LLMs, subtle but glaring discrepancies emerge across multiple components. Understanding the root psychological causes of LLM coding errors is essential to preventing them.

### Case 1: The "Inner Wrapper Div" that Destroys `justify-between` (Services / Feature Cards)
- **The Problem**: In equal-height feature cards (e.g. 298px secondary cards or 608px hero cards), the icons and text appear stuck together at the top, leaving an awkward empty void at the bottom.
- **Why AI Coders Diverge**:
  - In Figma Auto-Layout, the designer sets `primaryAxisAlignItems: SPACE_BETWEEN` between the top element (icon/badge) and bottom element (heading + description).
  - The AI web developer instinctively wraps all content inside a single container `<div>`:
    ```html
    <!-- BROKEN AI CODE: Only 1 direct child inside flex container! -->
    <article class="flex flex-col justify-between h-[298px]">
      <div> <!-- <-- THIS WRAPPER KILLS SPACE-BETWEEN -->
        <div class="icon">...</div>
        <h3 class="title">...</h3>
        <p class="desc">...</p>
      </div>
    </article>
    ```
  - Because there is only ONE direct child inside the flex container, `justify-between` has nothing to separate! Everything stays stuck at the top.
- **The Rule**: For any card using `justify-between`, there must be **exactly two direct child elements** (Top and Bottom):
  ```html
  <!-- CORRECT CODE: Exactly 2 direct children -->
  <article class="flex flex-col justify-between h-[298px]">
    <!-- Child 1: Top element -->
    <div class="w-7 h-7 flex items-center justify-center bg-line/60 border border-line">
      <img src="/icons/concept.svg" alt="Icon">
    </div>
    
    <!-- Child 2: Bottom element -->
    <div class="mt-6">
      <h3 class="font-display font-bold text-xl text-primary mb-3">Заголовок</h3>
      <p class="font-sans text-sm text-muted">Описание карточки</p>
    </div>
  </article>
  ```

---

### Case 2: The "AI Creative Drift & Card Surface" Syndrome (Contact Forms & Inputs)
- **The Problem**: The contact section on the website looks like a bloated dashboard card with heavy borders, rounded corners, and extra padding, while in Figma it was a sleek, minimal form integrated seamlessly into the page flow.
- **Why AI Coders Diverge**:
  - LLMs suffer from "creative drift" and template bias: pre-training data contains millions of tutorial sites where every contact form is wrapped in `<div class="card p-10 shadow-lg rounded-xl">`.
  - The AI coder assumes that wrapping the form in a card makes it look "prettier" or "more complete".
  - **The Reality**: Subjective embellishment by the AI is a **defect**. It alters the visual weight of the section, breaks the client-approved aesthetic, and shifts layout geometry.
- **The Rule**:
  - **Zero Unsolicited Containers**: NEVER add background cards, elevated surfaces, or decorative borders around forms unless explicit vector fills or frames exist in Figma.
  - If inputs in Figma sit directly on the section canvas (`bg-dark`), code them directly on `bg-dark`.
  - Always extract exact padding, border colors, and focus states directly from Figma Dev Mode.

---

### Case 3: The "12-Column Grid Reflex" Hallucination (Footers & Navigations)
- **The Problem**: In the footer, links and contact details are pushed hundreds of pixels too far apart, creating awkward gaps and unbalanced white space.
- **Why AI Coders Diverge**:
  - LLMs are trained on legacy Bootstrap / 12-column frameworks. When an LLM sees two columns, it automatically writes `grid grid-cols-12` (`col-span-4` + `col-span-8`).
  - In modern Figma design, the designer used **Flexbox Auto-Layout**:
    - `layoutMode: HORIZONTAL`
    - `itemSpacing: 64px` (`gap-16`)
    - Left column: `HUG` (content width, e.g. 240px)
    - Right column: `HUG` or `FILL`, starting immediately after the 64px gap.
  - In web code, `col-span-4` takes 33.3% of 1400px (= 466px), pushing the second column 200px further to the right than the designer intended!
- **The Rule**: **NEVER guess 12-column grids**. Inspect Figma Auto-Layout:
  - If `layoutMode: HORIZONTAL`, write `flex flex-col lg:flex-row gap-[X]`.
  - If a column is `HUG`, use `w-auto` or `shrink-0`. Do not stretch it with `col-span`.

---

### Case 4: The 9px/15px "Wild" Spacing Trap
- **The Problem**: AI designers without constraints generate arbitrary numbers: `margin: 9px`, `padding: 15px`, `gap: 23px`.
- **Why It Causes Chaos in Web**:
  - The coder is forced to write messy arbitrary Tailwind classes: `p-[15px] gap-[9px] min-h-[37px]`.
  - The site loses visual rhythm, leading to inconsistent padding across different pages and breakpoints.
- **The Rule**: Enforce the 4px/8px design contract upfront. In code, normalize any accidental Figma oddities to the nearest Tailwind standard step (`15px` -> `p-4` (16px), `9px` -> `gap-2` (8px)).

---

### Case 5: The "Phantom Borders & Decorative Dividers" Flaw
- **The Problem**: AI coders frequently add `<div class="border-t border-line">` between sections or inside footers where Figma has none.
- **The Rule**: Section transitions in modern dark/minimal design are created through **whitespace rhythm (`py-24`, `py-32`)** and subtle surface tone shifts (`#0E0E0D` vs `#141413`). NEVER inject decorative lines unless an explicit stroke exists in Figma.

---

### Container Formula & Responsive Padding (`px-5` / `px-3`)
- **Desktop (1440px canvas)**: **1400px inner content** + **20px (`px-5`) outer padding on each side** = **1440px max-width**.
- **Mobile (390px canvas)**: **`px-3` (12px)** or **`px-4` (16px)** with `w-full`.
- **CSS Definition**:
  ```css
  @layer components {
    .container {
      @apply w-full mx-auto px-3 sm:px-4 lg:px-5;
      max-width: 1440px; /* 1400px inner content + 2 * 20px (px-5) */
    }
  }
  ```

### Centralized CSS Component Architecture (`input.css` / `@layer components` via `@apply`)

> [!IMPORTANT]
> **NEVER scatter 15+ inline Tailwind utility classes across repetitive HTML elements (cards, buttons, inputs, badges). All reusable components, hover states, transitions, pseudo-elements, and form controls MUST be centralized in the main CSS input file (`resources/css/site.css` or `input.css`) using `@layer components` and `@apply`.**

#### Why Inlining Everything in HTML Fails:
1. **Visual Drift**: Updating button padding or border colors requires searching and editing 25 different template files.
2. **Template Bloat**: Cluttered HTML makes debugging auto-layout and flex structures extremely difficult.
3. **Pseudo-elements & Complex Hovers**: Tailwind utility syntax for pseudo-elements (`before:... after:... group-hover:...`) becomes unreadable and fragile.

#### Standard Component Library in `input.css`:
```css
@layer components {
  /* 1. Global Unified Container */
  .container {
    @apply w-full mx-auto px-3 sm:px-4 lg:px-5;
    max-width: 1440px; /* 1400px inner content + 2 * 20px (px-5) */
  }

  /* 2. Reusable Card Surfaces & Interactive Hovers */
  .card-surface {
    @apply bg-surface border border-line transition-all duration-300;
  }
  .card-surface:hover {
    @apply border-line-light;
  }
  .card-interactive {
    @apply card-surface relative overflow-hidden;
  }
  .card-interactive:hover {
    @apply border-gold/40 shadow-[0_0_25px_rgba(197,168,128,0.08)];
  }

  /* 3. Buttons & Action Links */
  .btn-primary {
    @apply inline-flex items-center justify-center gap-3 px-6 sm:px-8 py-3.5 bg-gold text-dark font-sans font-semibold text-sm tracking-wider uppercase transition-all duration-200 hover:bg-gold-hover hover:shadow-[0_0_20px_rgba(197,168,128,0.25)] active:translate-y-[1px];
  }
  .btn-secondary {
    @apply inline-flex items-center justify-center gap-3 px-6 sm:px-8 py-3.5 bg-transparent border border-line text-primary font-sans font-semibold text-sm tracking-wider uppercase transition-all duration-200 hover:border-gold hover:text-gold;
  }

  /* 4. Section Badges & Number Indicators */
  .section-badge {
    @apply inline-flex items-center gap-2 font-mono text-xs text-gold uppercase tracking-[0.16em] mb-4;
  }
  .section-badge-num {
    @apply text-dim font-bold mr-1;
  }

  /* 5. Form Elements */
  .input-field {
    @apply w-full h-[50px] bg-dark border border-line px-4 text-primary placeholder-dim/70 font-sans text-sm focus:border-gold focus:outline-none transition-colors rounded-none;
  }
  .input-textarea {
    @apply w-full bg-dark border border-line p-4 text-primary placeholder-dim/70 font-sans text-sm focus:border-gold focus:outline-none transition-colors rounded-none resize-y min-h-32;
  }
  .input-label {
    @apply block font-mono text-[11px] uppercase tracking-[0.14em] text-muted mb-2;
  }

  /* 6. Conversion "Sugar" Elements */
  .scroll-top-btn {
    @apply fixed bottom-6 right-6 z-40 w-11 h-11 bg-surface/90 border border-line text-primary flex items-center justify-center backdrop-blur transition-all duration-300 hover:border-gold hover:text-gold shadow-lg;
  }
  .floating-cta {
    @apply fixed bottom-20 right-6 z-40 bg-gold text-dark px-4 py-2.5 flex items-center gap-2.5 font-mono text-xs uppercase tracking-wider font-bold shadow-xl transition-transform hover:scale-105;
  }
  .cookie-banner {
    @apply fixed bottom-6 left-6 z-50 max-w-md bg-surface border border-line p-5 shadow-2xl;
  }
}
```

## Universal Rule: 100% Pre-filled Fallbacks in Admin (WordPress & Statamic)

> [!IMPORTANT]
> **A client opening the admin panel must NEVER see blank empty inputs relying on invisible template fallbacks. This is an absolute baseline across BOTH Statamic and WordPress (ACF Pro).**

1. **Why Template Fallbacks Are Not Enough**:
   - Writing `{{ hero_title ?? 'КАЖДЫЙ' }}` in the template protects against PHP errors, but the client opens the Control Panel and sees an empty input field. They have no idea what was originally there or what they are supposed to write.
2. **Statamic Implementation**:
   - In `content/collections/pages/home.md`: Pre-fill **every single key** with the actual production copy and asset filenames from Figma.
   - In `resources/blueprints/...`: Set `default:` for every field to match.
   - Add rich Russian `instructions:` starting with a visual location marker (`📍`).
3. **WordPress (ACF Pro) Implementation**:
   - In ACF field definitions: Always set `default_value` for every field matching the Figma design copy.
   - In Theme Setup / Migration Seeder (`functions.php` or `seeds/`): Programmatically seed initial post meta on theme activation:
     ```php
     if (!get_post_meta($homepage_id, 'hero_title_1', true)) {
         update_field('hero_title_1', 'КАЖДЫЙ', $homepage_id);
         update_field('hero_title_highlight', 'BIM-МОДЕЛЬ', $homepage_id);
     }
     ```

## Performance & Font Loading: Zero Layout Shift (CLS = 0.000)

- Use **Variable Fonts** (`Inter Variable`, `JetBrains Mono Variable`) in modern `woff2` format (Cyrillic + Latin subsets).
- **Preload** primary fonts in `<head>`:
  ```html
  <link rel="preload" href="/fonts/inter-var-cyrillic.woff2" as="font" type="font/woff2" crossorigin>
  <link rel="preload" href="/fonts/inter-var-latin.woff2" as="font" type="font/woff2" crossorigin>
  ```
- Put **critical `@font-face` CSS inline** in `<head>` before external stylesheets with `font-display: swap` to eliminate FOUT/FOIT.

## Antlers Syntax & Modifiers Rules (Statamic)

- **CRITICAL GOTCHA**: In Statamic Antlers, there is **NO `default` modifier**! Using `{{ value | default('fallback') }}` triggers `Statamic\Modifiers\ModifierNotFoundException: Modifier [default] not found` and causes a 500 error!
- **Rule**: ALWAYS use native Antlers null coalescing: `{{ variable ?? 'fallback' }}` or `{{ variable or 'fallback' }}`.
- **Dynamic Asset Binding**: When referencing images, always use:
  ```html
  <img src="{{ image:url ?? image ?? '/images/fallback.jpg' }}" alt="{{ image:alt ?? title }}">
  ```
- **Asset Filenames in YAML**:
  - Fields using `type: assets`, `container: assets` must store the relative filename in YAML frontmatter (e.g. `image: project-autoset.jpg`), **NOT** `/images/project-autoset.jpg`!
  - Copy all media files and SVG icons into the asset container directory (`public/assets/`).

## Interactive Sliders & Dynamic Carousels

- Quote sliders, facts carousels, and client testimonials must **NOT** have their content hardcoded in JavaScript.
- Expose them as a Grid/Repeater field in the CMS (`why_us_facts`).
- Pass data into client JS using a JSON island:
  ```html
  {{ if why_us_facts }}
    <script id="why-us-data" type="application/json">
      {{ why_us_facts | to_json }}
    </script>
  {{ /if }}
  ```
- In client JS, read `#why-us-data` and dynamically generate slides, indicators, and counters.

## ISPmanager 6 Deployment Pipeline

Do not invent custom transports: tested repository scripts exist with byte-level verification. For hosting specifics, see the `ispmanager-hosting` skill; for FastUp WordPress specifics, see `integrations/wordpress.md`.

```bash
python scripts/deploy_theme.py --drift     # inspect differences against production
python scripts/deploy_theme.py --sync      # deploy differences via FTP + purge cache
python scripts/deploy_static_file.py <file> --site <domain> --remote-name <name>
```

Repository scripts automatically create local backups of the live version, verify written content via readback, and rollback on discrepancy. Binaries and precision files always deploy via FTP.

**Banned Anti-Patterns:**
- **Never drop PHP execution runners in webroot:** Do not upload temporary PHP scripts (e.g. `deploy_runner.php`) expecting `unlink(__FILE__)` to clean them up. Webroots are publicly readable.
- **Never base64-encode files to bypass encoding:** The ISPmanager `file.edit` API with `encoding: 'UTF-8'` preserves Cyrillic perfectly.
- **Never automate browser clicks for file uploads:** Use direct passive FTP to the server IP or website domain (not behind Cloudflare).

**Document Root Verification:**
- WordPress: `/www/<domain>/`
- Statamic & Laravel: `/www/<domain>/public`
Always verify the domain's document root in the hosting panel before deployment.

## Mandatory UX Polish & Conversion Elements ("Sugar")

Always automatically implement the following four components styled to match the visual theme:
1. **Breadcrumbs + Schema.org JSON-LD**: Structured data script `<script type="application/ld+json">`.
2. **Scroll To Top Button**: Floating button at `fixed bottom-6 right-6 z-40`, smoothly fades in after 400px scroll.
3. **Floating CTA Widget**: Sticky conversion button at `fixed bottom-20 right-6 z-40` with messenger links (Telegram, WhatsApp) and smooth scroll to contact form.
4. **Cookie Consent Banner**: Non-intrusive floating notice at bottom-left (`fixed bottom-6 left-6 max-w-md z-50`) with `localStorage` persistence.

## Deployment Verification

Validate deployed pages using an HTTP request with a standard browser `User-Agent`: check response status (200 OK), presence of critical DOM elements, and Cyrillic character integrity.
