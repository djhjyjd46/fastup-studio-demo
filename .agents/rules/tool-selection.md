# Принцип выбора инструментов (Google Non-Agentic First)

В соответствии с официальными рекомендациями Google Cloud Architecture (*«Choose a design pattern for your agentic AI system»*), агент соблюдает строгую иерархию исполнения:

## 1. Иерархия решений
1. **Одна атомарная операция** (получить данные лида, создать задачу, выгрузить отчёт):
   - Решается вызовом **Инструмента** (`tools.fastup.by` через `scripts/tools.py` или локального Python-скрипта в `scripts/`).
   - Запрещено писать новый скрипт, если в `scripts/tools.py list` или `scripts/` уже есть готовый инструмент.
2. **Предсказуемый процесс / ранбук** (создать акт по шаблону, рассчитать налог, проверить маркеры текста, собрать КП):
   - Решается как **Процедура (Skill)**.
   - Исполняется ведущим агентом пошагово по инструкции `SKILL.md`. Не создавать субагентов для простых чек-листов.
3. **Глубокое исследование с огромным объёмом сырых данных** (парсинг 50 страниц сайта, выгрузка тысяч поисковых запросов рекламы):
   - Запускается **Субагент** (`invoke_subagent`) с изолированным контекстом.
   - Сырой HTML, спарсенные страницы и гигантские JSON сохраняются во внешние хранилища (`fastup-clients/<клиент>/`), а в основной диалог фаундеру возвращается только чистая выжимка.

## 2. Языковой стандарт скиллов
- **Технические, алгоритмические и SEO/GEO-скиллы** (`aeo-geo`, `geo-rag-architect`, `figma-to-cms`, веб-разработка) пишутся на **английском языке** для максимальной точности рассуждений модели и экономии токенов.
- **Бухгалтерские, юридические и локальные скиллы** (`fastup-accountant`, `fastup-doc-ops`, `fastup-tg-agent`) содержат структуру на английском/русском, но **все законы РБ, статьи НК РБ, названия налогов, формулы вычетов и стоп-слова фиксируются строго на русском языке** буква в букву для исключения правовых галлюцинаций.
